# Desby OS - AI Agent Instructions

## Project Overview
Desby OS is a Flutter-based digital operating system for tailors and fashion entrepreneurs. It follows Clean Architecture with Riverpod for state management.

## Key Technologies
- **Framework**: Flutter (Dart SDK ^3.11.5)
- **State Management**: Riverpod
- **Architecture**: Clean Architecture (Presentation → Domain → Data)
- **Code Generation**: Freezed, Riverpod Generator, JSON Serializable
- **Local Storage**: Hive, SharedPreferences
- **Networking**: Dio
- **Backend**: Supabase (Auth, Postgres, Storage) — *not* Firebase; the
  Firebase references that used to live here were stale
- **Payments**: Flutterwave (`flutterwave_standard`) — verified server-side via
  the `flutterwave-pay` / `flutterwave-verify` Supabase Edge Functions. There is
  no Paystack package in `pubspec.yaml` and the `Paystack*` classes in
  `payments/domain/exceptions/` are dead code.
- **Database IDs**: `orders.id` is a **uuid**. Human-readable handles live in
  `orders.reference` (`ORD_`/`MKT_`/`PUR_` prefix) and are generated by
  `OrderIds` in `features/orders/domain/entities/order_ids.dart`. Never
  hand-write an order id at a call site.
- **Order identity**: `orders.requesting_user_id` = the Desby account that
  placed the request; `orders.client_id` = the *tailor's* customer record
  (`clients.id`), null until fulfilment. These are not interchangeable.

## Coding Conventions
- Files: `snake_case.dart`
- Classes: `PascalCase`
- Functions/Variables: `camelCase`
- Constants: `camelCase` (not UPPER_SNAKE_CASE)
- 2-space indentation
- Always use `const` constructors when possible
- Always use `final` for immutable variables
- Use non-nullable types by default
- Organize imports: Dart → Flutter → Packages → Relative

## Architecture Guidelines
1. **Presentation Layer**: Pages, Widgets, Providers (Riverpod)
2. **Domain Layer**: Entities, Repository interfaces, Usecases (pure Dart)
3. **Data Layer**: Models, Datasources, Repository implementations

## When Making Changes
1. Follow the existing feature module structure
2. Keep business logic in the domain layer
3. Use Riverpod providers for dependency injection
4. Write tests for new functionality
5. Run `flutter analyze` and `dart format .` before committing
6. Follow the commit message format: `type(scope): description`

## Important Notes
- Never hardcode secrets; use `.env` files with `flutter_dotenv`
- Use `flutter_secure_storage` for sensitive data
- Prefer const constructors for performance
- Use sealed classes for type safety where appropriate
- Keep widgets small and focused

## Supabase / postgrest Gotchas
- **`postgrest` >= 2.9 REMOVED `PostgrestResponse.error`.** `PostgrestResponse`
  now has only `data` and `count`. A failed request THROWS
  `PostgrestException` instead of returning an error field.
- So the old pattern is a runtime bug, not a compile error, whenever the result
  is accessed dynamically or through an extension:
  `if (res.error != null) {...}` → `NoSuchMethodError` (mangled, e.g. `gdu`).
- Correct pattern: `try { await client.rpc(...); } on PostgrestException catch (e) { ... }`
  or `on PostgrestException catch (e)` when the throw is async.
- `PostgrestException` exposes `message`, `code`, `details`. Prefer `message`.
- Known fixed sites: `tailor_onboarding_page.dart` (`complete_tailor_onboarding`),
  `marketplace_cart_page.dart` (`orders` insert).
- `test/postgrest_no_error_field_test.dart` guards this contract.
- Our SQL functions (`complete_tailor_onboarding`) `RAISE EXCEPTION` on failure,
  which now surfaces as a thrown `PostgrestException` — that is expected, not a
  crash. Handle it and show a readable message.

## Debugging Minified Dart Errors (`NoSuchMethodError: method not found: 'xxx'`)
- dart2js mangles identifiers in release builds, so a short name like `gdu` is
  useless for grepping your own source. Never assume the mangled name maps to a
  symbol you can find in `main.dart.js`.
- **To localize one, instrument — do not do bundle archaeology.** Track a
  `stage` string through the try block and use `catch (e, st)` +
  `debugPrintStack`. The Snackbar alone hid this bug for hours because it only
  showed `e.toString()`.
- To prove the browser runs current code, compare hashes instead of downloading
  6MB bundles: `shasum -a 256 build/web/main.dart.js` vs
  `ssh ... sha256sum /var/www/desby/app/main.dart.js`.
- O0 and release builds mangle DIFFERENTLY (`J.ec` vs `J.eb` for identical logic),
  so an O0 build cannot map release symbol names.
- Then read the real stack frame's line in `build/web/main.dart.js` locally — it
  is identical to the remote bundle, so no download is needed.
